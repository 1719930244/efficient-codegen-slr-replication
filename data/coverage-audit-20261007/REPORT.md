# 覆盖度审计报告（1007）：2,110 篇检索截断的替代检验

## 为什么做替代检验
原始的 Stage-1 记录（22,118 条）、3,810 篇排名表、分类器代码和 1,700 篇全文判定都不在本机、复现包或两个 git 仓库中。协议文档记载这些文件原在 `/home/szw/overleaf/efficient-codegen-survey/data/`，所在的 A800 已退租。因此 2,110 篇无法原样找回。替代办法是独立重检加概率抽样：用同一检索式在 OpenAlex 上重检原窗口，从语料以外的记录中随机抽样筛选，估计漏检规模。

## 方法
- 检索：OpenAlex `title_and_abstract.search`，A∧B∧C 三组检索式，窗口 2017-01-01 至 2026-03-06（原数据库检索日）。执行时间 2026-10-07，命中 3,891 条，下载 3,894 条（query-meta.json，query.py、fetch.py）。
- 与语料对齐：按 DOI、arXiv 号和标题相似度对齐，OpenAlex 召回语料 99 篇（corpus-matched.json）。未召回的 42 篇多为 3 月之后发表或来自滚雪球。
- 抽样：语料以外的 pool 共 3,792 条，按种子 20261007 简单随机抽取 400 条（sample.jsonl）。
- 筛选：筛选器 A 为 gpt-6-astra，筛选器 B 为 qwen3-max，均按 IC1、IC2、IC3、EC2、EC3、EC4 做标题与摘要判定（screenA/B.jsonl）。两者一致率 0.882，κ = 0.708。**这是两个模型之间的一致性，不是人工评分者间信度，不能填进正文 kappa 的占位。**
- 裁决：凡有任一筛选器未排除的记录共 123 条，由 Claude（审计子代理）逐条按摘要裁决（adjudicate.md、adjudication.json）。**作者需要复核。**

## 结果
- 其他版本：R058、R077、R171 是语料中已有论文的其他版本，不计入漏检。
- 合格，摘要层面已确认：3 篇。
  - R028：面向编码任务的 RAG 示例检索器，报告检索时间与 44 倍加速。
  - R288：面向无人机控制代码生成的混合蒸馏小模型。
  - R356：纯 CPU 的 LLM 代码生成基准，报告推理时间、内存、CPU 占用和能耗。
- 合格，待全文核查：2 篇。
  - R124 PennyCoder：摘要未报效率指标，IC4 需看全文。
  - R133「Don't Complete It!」：ICSE-Companion 论文，EC4 的页数要求需核实。
- 边界项：30 篇，多为把代码生成列为若干任务之一的通用 LLM 效率方法，是否纳入取决于 IC3 怎么界定。

## 局限（作者须知）
1. OpenAlex 的覆盖面与七个数据库不同。估计的是 OpenAlex 可见部分的召回率，不是专门针对 2,110 篇尾部的召回率。
2. 筛选与裁决是自动化完成的，合格记录和边界项都需作者确认。若作者把边界项中的一部分判为合格，召回率会明显下降。
3. 只覆盖 3 月窗口。4 月至 8 月由检索更新覆盖。
4. **须主公决定**：把 3 到 5 篇合格研究加入语料（141 篇将变为 144 至 146 篇，全文计数需要重算），还是维持现在「报告而不加入」的写法。
